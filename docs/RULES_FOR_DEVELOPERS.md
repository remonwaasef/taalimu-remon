# قواعد جودة وأمان الكود (RULES FOR DEVELOPERS)

> **هام:** يجب على جميع المطورين الالتزام بهذه القواعد دون استثناء لضمان استقرار وأمان منصة Taalimu.

---

## أولاً: تنظيف الكود وتحسين الأداء
1.  **الكود الميت:** يجب إزالة أي دوال، متغيرات، أو كلاسات غير مستخدمة فوراً.
2.  **مبدأ DRY:** يمنع تكرار الكود؛ استخدم الـ Traits أو Services لتوحيد المنطق المكرر.
3.  **تحسين الاستعلامات:** يمنع استخدام أنماط N+1 Queries. يجب دائماً استخدام **Eager Loading** (`with()`) عند التعامل مع العلاقات.
4.  **الأصول (Assets):** يجب ضغط الصور والملفات الكبيرة قبل رفعها.

## ثانياً: حماية قواعد البيانات والنسخ الاحتياطي
1.  **النسخ الاحتياطي:** يجب أخذ نسخة احتياطية كاملة قبل أي تغيير في بنية قاعدة البيانات.
2.  **الـ Migrations:** جميع التعديلات تتم حتماً عبر نظام الـ migrations. يمنع تعديل الجداول يدوياً في قاعدة البيانات.
3.  **الاختبار:** يجب اختبار الـ migrations في بيئة تجريبية قبل اعتمادها.

## ثالثاً: معايير الأمان (Security)
1.  **SQL Injection:** فحص الاستعلامات بدقة لمنع ثغرات الحقن.
2.  **CSRF:** التحقق من وجود توكن الحماية في جميع الطلبات (POST, PUT, DELETE).
3.  **السرية:** يمنع كتابة مفاتيح سرية أو كلمات مرور في الكود مباشرة؛ استخدم ملف `.env`.
4.  **الصلاحيات:** مراجعة صلاحيات الملفات الحساسة لمنع الوصول العشوائي.

## رابعاً: الاستقرار ومراجعة الأخطاء
1.  **الترجمة (Localization):** يمنع كتابة نصوص مباشرة في الكود. يجب نقل جميع النصوص لملفات الترجمة (`resources/lang`).
2.  **معالجة الأخطاء:** يجب إحاطة العمليات الحساسة بـ `try-catch` مناسب.
3.  **التحقق (Validation):** يجب وجود Validation كافٍ وصارم لجميع مدخلات المستخدم.
4.  **التسمية:** فرض معيار موحد لتسمية الملفات والكلاسات (CamelCase للـ Classes، snake_case للمتغيرات).

## خامساً: جودة الهيكلة (Clean Code)
1.  **Single Responsibility:** الـ Function يجب أن تؤدي وظيفة واحدة فقط. إذا كبرت، قم بتقسيمها.
2.  **تجنب التعقيد:** تجنب الحلقات المتداخلة (Nested Loops) والشروط المعقدة.
3.  **سهولة القراءة:** اكتب كوداً واضحاً، واستخدم التعليقات لشرح "لماذا" تم اختيار حل معين للأجزاء المعقدة.

## سادساً: قواعد الاختبار (Testing)
1.  **المسارات الحرجة:** يجب كتابة Feature Tests للعمليات الأساسية (الدفع، التسجيل، الدخول).
2.  **البيانات الوهمية:** استخدم **Factories & Fakers** دائماً في الاختبارات؛ يمنع استخدام بيانات حقيقية.
