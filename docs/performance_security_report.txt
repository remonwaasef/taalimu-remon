1. سلسلة Middleware للأمان (ترتيب التنفيذ)
================================================================================

كل طلب HTTP يمر عبر 7 Middleware بهذا الترتيب:
  1. IdentifyTenant         - عزل بيانات المستأجر
  2. SetLocale              - تحديد اللغة (ar/en/fr)
  3. ContentSecurityPolicy  - CSP + HSTS + رؤوس أمان HTTP
  4. SecurityHeaders        - رؤوس أمان إضافية
  5. BasicWAF               - حظر SQL Injection / XSS / Path Traversal
  6. PaginationLimit        - منع الطلبات الضخمة (حد أقصى 100 سجل)
  7. throttle:300,1         - تحديد معدل الطلبات

Middleware خاص بالمسارات:
  • CheckSubscription    - التحقق من اشتراك فعال
  • CheckFeature         - التحقق من صلاحية الميزة في الباقة
  • CheckAdminRole       - صلاحية Super Admin فقط
  • ForcePasswordChange  - إجبار تغيير كلمة المرور
  • EnsureOnboardingCompleted - التأكد من إتمام الإعداد الأولي
  • TwoFactorMiddleware  - ⚠️ STUB (غير مفعل!)
  • EnsurePhoneIsVerified - ⚠️ STUB (غير مفعل!)

2. جدار حماية تطبيقات الويب (BasicWAF)
================================================================================

الهجمات المكتشفة والمحظورة:
  • SQL Injection  - SELECT/UNION/INSERT/UPDATE/DELETE/DROP/CREATE/ALTER
  • XSS           - <script>، javascript:، on*=
  • Path Traversal - ../، ..\\، /etc/passwd

المدخلات المفحوصة:
  • جميع بيانات الطلب (بشكل متكرر)
  • Query parameters
  • User-Agent، Referer headers

المسارات المستثناة: auth/google/*، login*، register*، payment/*، webhooks/*

الإجراء: تسجيل في security.log + إرجاع 403 Forbidden

3. سياسة أمان المحتوى (CSP) - الإنتاج
================================================================================

default-src  'self'
script-src   'self' 'unsafe-inline' 'unsafe-eval' https: cdn.jsdelivr.net
style-src    'self' 'unsafe-inline' https: cdn.jsdelivr.net fonts.googleapis.com
font-src     'self' data: https: fonts.gstatic.com
img-src      'self' data: blob: https:
connect-src  'self' https:
frame-src    'self' https://www.youtube.com https://player.vimeo.com https://js.stripe.com
frame-ancestors 'none'
base-uri     'self'

رؤوس إضافية:
  • X-Content-Type-Options: nosniff
  • X-Frame-Options: DENY
  • X-XSS-Protection: 1; mode=block
  • Referrer-Policy: strict-origin-when-cross-origin
  • Permissions-Policy: geolocation=(), microphone=(), camera=(self)
  • HSTS: max-age=31536000; includeSubDomains; preload (إنتاج فقط)

5.2. حدود العمارة الحالية (تقديرات)

  ----------------------------------|----------------------
  بدون Redis (DB cache + queue)     | 500 - 2,000 مستأجر

7.1. تحسين الذاكرة (Chunking & Lazy Loading)
  الموقع                    | الطريقة              | الهدف
  --------------------------|----------------------|---------------------------
  ImportStudentsJob         | LazyCollection + chunk(500) | استيراد Excel بدون تحميل كامل

  StudentProfileService     | ->lazy(1000)         | تحميل ملفات الطلاب بشكل متدرج
  StudentImportService      | array_chunk(500)     | إدخالات مجمعة في DB

7.2. المهام المجدولة (Scheduled Tasks)
  • جميع المهام تستخدم withoutOverlapping() ✅ (تمنع التكرار)
  • 4 مهام يومية مجدولة
  • خطورة: كلها تعمل على خادم واحد - قد تتعارض مع خوادم متعددة

7.3. استعلامات خام (Raw Queries)
  • DB::raw(): استخدام محدود (7 مرات) - توابع تجميعية فقط (SUM, COUNT)
  • DB::select/statement/unprepared: ❌ غير مستخدمة
  • لا توجد استعلامات غير مقيدة

7.4. منع N+1
  • preventLazyLoading: مفعل في بيئة التطوير فقط ✅
  • Eager Loading: مستخدم بكثافة في جميع Services ✅
  • تحسينات يدوية لـ N+1: موجودة مع تعليقات ✅

10. التوصيات
================================================================================

توصيات فورية (قبل إضافة خوادم إضافية):
  1. 🔴 تفعيل Redis للكاش: CACHE_STORE=redis
  2. 🔴 تفعيل Redis للطوابير: QUEUE_CONNECTION=redis
  3. 🔴 تغيير التخزين إلى S3/NFS: FILESYSTEM_DISK=s3
  4. 🟡 تكوين Read Replica: DB_READ_HOST=<replica-host>

توصيات قصيرة المدى:
  5. 🟡 نشر وتكوين Octane (php artisan octane:install)
  6. 🟡 تمركز السجلات عبر Sentry/Papertrail
  7. 🟡 مشاركة كاش views عبر الخوادم أو regenerating أثناء النشر
  8. 🟡 إعداد Redis مع اتصالات دائمة (persistent connections)

توصيات متوسطة المدى:
  9. 🟢 التوجه إلى حاويات (Docker/Kubernetes) للتوسع التلقائي
  10. 🟢 تطبيق CI/CD مع نشر بدون توقف (zero-downtime)
  11. 🟢 إضافة Read Replicas لاستعلامات التحليلات الثقيلة
  12. 🟢 دراسة نموذج Tenant Per Database للتوسع الهائل (100k+ مستأجر)
