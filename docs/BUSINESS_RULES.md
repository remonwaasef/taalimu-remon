# 💼 Business Rules — قواعد الأعمال لمنصة Taalimu

> آخر تحديث: مايو 2026
> هذه الوثيقة تشرح **قواعد الأعمال** التي يبني عليها النظام قراراته.
> أي تغيير في هذه القواعد يتطلب تعديل الكود المقابل.

---

## 1. دورة حياة المركز (Tenant Lifecycle)

```
                 تسجيل جديد
                      │
                      ▼
              ┌───────────────┐
              │   Trial       │ ← فترة تجريبية مجانية
              │  (7-30 يوم)   │
              └───────┬───────┘
                      │
            ┌─────────┼─────────┐
            ▼                   ▼
   ┌──────────────┐    ┌──────────────┐
   │   Active     │    │   Expired    │ ← لم يدفع
   │  (مشترك)     │    │  (منتهي)     │
   └──────┬───────┘    └──────┬───────┘
          │                   │
          ▼                   ▼
   ┌──────────────┐    ┌──────────────┐
   │  Renewal     │    │  Grace       │ ← مهلة 7 أيام
   │  (تجديد)     │    │  Period      │
   └──────────────┘    └──────┬───────┘
                              │
                              ▼
                       ┌──────────────┐
                       │  Suspended   │ ← البيانات محفوظة 30 يوم
                       │  (معلّق)      │
                       └──────────────┘
```

### القواعد:
| القاعدة | التفاصيل |
|:---|:---|
| الفترة التجريبية | تُحدد في `packages.trial_days` (0 = بدون تجريبية) |
| تنبيه انتهاء | يُرسل قبل 7 أيام من الانتهاء (Email + Telegram) |
| بعد الانتهاء | المركز يرى صفحة "جدد اشتراكك" — لكن بياناته محفوظة |
| الحذف النهائي | لا يحدث تلقائياً — يتطلب قرار يدوي من Super Admin |

## 2. نظام التسعير والعملات

### دورات الدفع:
| الدورة | الحساب | المعرّف |
|:---|:---|:---|
| شهري | `package.price` | `monthly` |
| ترم (4 أشهر) | `package.term_price` أو `price × 4` | `term` |
| سنوي (10 أشهر) | `package.yearly_price` أو `price × 10` | `yearly` |

### العملات المدعومة:
| العملة | بوابة الدفع | القيد |
|:---|:---|:---|
| EGP (جنيه مصري) | Paymob | متاح فقط من داخل مصر (GeoIP check) |
| USD (دولار) | PayPal / Stripe | متاح عالمياً |
| EUR (يورو) | PayPal / Stripe | متاح عالمياً |

### قواعد العملة:
- **ممنوع:** دفع EGP من خارج مصر (يُفحص عبر GeoIPService)
- **ممنوع:** استخدام PayPal لدفع EGP
- **ممنوع:** استخدام Paymob لدفع USD/EUR
- الأسعار الإقليمية تُخزّن في `packages.regional_prices` (JSON)

## 3. نظام الكوبونات

### أنواع الكوبونات:
| النوع | المعرّف | الحساب |
|:---|:---|:---|
| نسبة مئوية | `percentage` | `السعر × (القيمة / 100)` |
| مبلغ ثابت | `fixed` | `min(القيمة, السعر)` — لا يتجاوز السعر |

### شروط صلاحية الكوبون:
```
✅ صالح إذا:
  - is_active = true
  - starts_at <= الآن (أو بدون تاريخ بداية)
  - expires_at >= الآن (أو بدون تاريخ انتهاء)
  - used_count < max_uses (أو بدون حد أقصى)

❌ غير صالح إذا:
  - معطّل
  - لم يبدأ بعد
  - منتهي الصلاحية
  - تجاوز حد الاستخدام
```

### قاعدة الربط بالباقة:
- لو `coupon.package_id` موجود → الكوبون يعمل فقط مع هذه الباقة
- لو `coupon.package_id` = null → يعمل مع أي باقة

## 4. نظام الصلاحيات والأدوار

### الأدوار (7 أدوار):
| الدور | المعرّف | الصلاحيات الرئيسية |
|:---|:---|:---|
| مدير النظام | `super_admin` | كل شيء (إدارة كل المراكز) |
| مدير مركز | `center_admin` | كل شيء داخل مركزه |
| سكرتير | `secretary` | الطلاب + الجداول + الحضور + المبيعات |
| محاسب | `accountant` | المالية فقط (مبيعات + مصروفات + تقارير) |
| مدرّس | `instructor` | الدورات + طلابه + حضوره + امتحاناته |
| موظف | `staff` | عرض فقط (بدون تعديل) |
| طالب | `student` | عرض الدورات فقط |

### قاعدة العزل (Tenant Isolation):
- كل مستخدم يرى **فقط** بيانات مركزه (`tenant_id`)
- الـ `super_admin` يرى كل المراكز
- Spatie Permissions يستخدم `teams` = `tenant_id`

## 5. حدود الاستخدام (Feature Limits)

### كيف يعمل نظام الحدود:
```
المركز يحاول إضافة طالب جديد
    │
    ▼
SubscriptionService::checkLimit($tenant, 'max_students')
    │
    ├── هل لديه اشتراك فعّال؟ ← لا → ❌ ممنوع
    │
    ├── هل الميزة مُفعّلة في الباقة؟ ← لا → ❌ ممنوع
    │
    ├── هل الحد = -1 (غير محدود)؟ ← نعم → ✅ مسموح
    │
    └── هل الاستخدام الحالي < الحد؟ ← نعم → ✅ مسموح
                                       لا → ❌ ممنوع
```

### الحدود المتاحة:
| الكود | الوصف | النوع |
|:---|:---|:---|
| `max_students` | عدد الطلاب | رقم / -1 |
| `max_instructors` | عدد المدرسين | رقم / -1 |
| `max_courses` | عدد الدورات | رقم / -1 |
| `max_classrooms` | عدد الفصول | رقم / -1 |
| `max_branches` | عدد الفروع | رقم / -1 |
| `whatsapp_enabled` | إشعارات واتساب | boolean |
| `reports_enabled` | التقارير المتقدمة | boolean |

### تنبيه الحد (90% Threshold):
- عند وصول 90% من الحد → يُرسل تنبيه Telegram تلقائياً
- التنبيه يُرسل مرة واحدة يومياً فقط (لمنع الإزعاج)

## 6. نظام الدفع (Payment Flow)

### التسجيل الجديد:
```
1. العميل يختار: باقة + دورة دفع + عملة + كوبون (اختياري)
2. النظام يحسب: السعر النهائي = السعر الإقليمي - الخصم
3. لو الباقة مجانية (trial_days > 0):
   → يُفعّل الاشتراك التجريبي فوراً
4. لو الباقة مدفوعة:
   → يُوجّه لبوابة الدفع (PayPal أو Paymob)
   → بعد الدفع الناجح → PaymentProcessingService يُفعّل الاشتراك
```

### بعد الدفع الناجح:
```
PaymentProcessingService::activateSubscription()
  │
  ├── 1. إنشاء/تحديث Subscription (status = active)
  ├── 2. تسجيل الكوبون (increment usage)
  ├── 3. إرسال إشعار Telegram للمدير
  ├── 4. تسجيل العملية في Activity Log
  └── 5. إعادة التوجيه لصفحة النجاح
```

### التجديد:
- حالياً **يدوي** — العميل يضغط "جدد" ويدفع مرة أخرى
- مخطط مستقبلاً: Recurring Billing تلقائي

## 7. نظام الحضور والغياب

### القواعد:
- يمكن تسجيل الحضور عبر: QR Code / يدوي / ماسح باركود
- عند تسجيل حضور → يُرسل إشعار WhatsApp لولي الأمر (لو مفعّل)
- الطالب الغائب 3 مرات متتالية → تنبيه للمدرس

## 8. نظام المبيعات (Sales)

### أنواع الدفع:
| النوع | الوصف |
|:---|:---|
| دفع كامل | المبلغ بالكامل |
| أقساط | دفعة أولى + أقساط شهرية |

### قواعد الأقساط:
- القسط المتأخر يُولّد تذكير تلقائي
- يمكن تعديل جدول الأقساط يدوياً
- لا يُمنع الطالب من الحضور بسبب تأخر القسط (قرار إداري)

---

## 9. Auto-Provisioning (التجهيز التلقائي)

### عند تسجيل مركز جديد:
```
1. إنشاء Tenant (الكيان)
2. إنشاء User (المدير) + Instructor Profile
3. تعيين الأدوار والصلاحيات (Spatie)
4. زرع بيانات تجريبية (DemoDataService):
   - مراحل دراسية (ابتدائي، إعدادي، ثانوي)
   - صفوف (1-12)
   - مواد أساسية
5. إرسال إشعار Telegram
6. (مخطط) إنشاء CNAME في Cloudflare
```
